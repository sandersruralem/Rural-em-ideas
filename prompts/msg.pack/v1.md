# Prompt: `msg.pack`

| Field | Value |
| --- | --- |
| **ID** | `msg.pack` |
| **Version** | v1 |
| **Status** | Draft — untested |
| **Job** | Turn one set of approved facts into consistent public messages for every channel |
| **Recommended tool** | Claude Pro or Gemini Pro for approved public facts; Microsoft Copilot if the fact set is not yet releasable |
| **Data level** | Green, or Yellow in Copilot once authorized. Never Red. |
| **Reviewer** | Emergency Manager or equivalent, plus PIO where that role exists |

Job playbook: [public-message-pack.md](../../docs/job-playbooks/public-message-pack.md)

---

## When to use

When approved facts need to reach the public through several channels at once and the versions must
not contradict each other.

## When not to use

- Before the facts are approved for release
- For anything involving a named individual, casualty, or law-enforcement matter
- For rumor control — that needs a stricter prompt, still in the backlog
- For translation — English only in v1

## Required inputs

| Input | Source | Notes |
| --- | --- | --- |
| County fact pack | `context/county-fact-pack.md` | Always |
| Approved facts | Emergency Manager | Short declarative bullets only |
| Situation type | Operator | Outage, flood, winter storm, boil water, closure, shelter opening |
| Audience | Operator | Whole county, a town, a corridor |
| Action requested | Emergency Manager | What the public should actually do |
| Effective time and next update | Operator | Include the time zone |
| Official contact point | Published sources | Never a personal cell number |
| Channels needed | Operator | Which variants are actually going out |

## Optional inputs

| Input | Effect |
| --- | --- |
| Alert character limit | Constrains the mass-notification variant |
| Tone guidance | Adjusts urgency, within plain-language limits |
| Prior message in the series | Keeps a running incident consistent |

## System block

```text
You are assisting a small rural county emergency management office in the United States
with public information and warning. You are drafting public messages for review.

Rules that apply to every response:
- Use only the approved facts provided. Do not add, extend, soften, or dramatize them.
  Do not add reassurance, causes, timelines, or consequences that were not provided.
- Never invent a shelter, hotline, hours of operation, road status, cause, or casualty
  or damage figure. If a needed fact is missing, write UNKNOWN in the draft and list it
  under "Information Needed."
- Every channel version must state the same facts, the same instruction, and the same
  times. They must not contradict each other.
- Put the action the public should take in the first two sentences of every version.
- Write in plain English at roughly a sixth-to-eighth-grade reading level. Short
  sentences. No jargon, no acronyms the public would not know, no emergency-management
  terminology.
- State all times with the time zone. Do not compute or convert times.
- Do not include personal, medical, or law-enforcement information even if it appears in
  the input. If you see any, stop and say so instead of processing it.
- English only. Do not translate.
- This is a draft for human review, not an approved public message.
- Follow the output structure exactly. Do not add sections or commentary.
```

## User block

```text
Draft a public message pack from the approved facts below.

COUNTY FACT PACK:
<paste the county fact pack>

SITUATION TYPE:
<outage / flood / winter storm / boil water / road closure / shelter opening / other>

AUDIENCE:
<whole county / named town / named corridor>

APPROVED FACTS (use only these):
<short declarative bullets>

ACTION REQUESTED OF THE PUBLIC:
<what people should do>

EFFECTIVE TIME AND NEXT UPDATE:
<time, time zone, and when the next update will come>

OFFICIAL CONTACT POINT:
<published phone number or web page>

CHANNELS NEEDED:
<website / social / alert text / radio script / FAQ>

ALERT CHARACTER LIMIT:
<number, or write "not applicable">

OUTPUT FORMAT:
1. Website Update — 150 to 250 words
2. Social Post — 50 to 80 words
3. Mass Notification Text — within the stated character limit, with the character count
   shown in parentheses at the end
4. Radio Read Script — about 30 seconds when read aloud, marked for reading
5. FAQ — three to six question-and-answer pairs
6. Information Needed — facts this message should include but that were not provided

Produce only the channels listed above. Skip the others.
```

---

## Expected output schema

1. Website Update
2. Social Post
3. Mass Notification Text
4. Radio Read Script
5. FAQ
6. Information Needed

## Acceptance criteria

- [ ] Every requested channel is present, and no unrequested channel is added
- [ ] No fact appears in any version that was not in the approved input
- [ ] All versions state the same facts, instruction, and times
- [ ] The requested action appears in the first two sentences of every version
- [ ] Alert text is within the stated character limit
- [ ] Radio script reads naturally aloud in roughly 30 seconds
- [ ] All times carry a time zone
- [ ] Contact point matches the input exactly
- [ ] Plain language; no jargon or emergency-management terminology
- [ ] Missing facts appear under Information Needed rather than being filled in
- [ ] Output matches the schema exactly

## Review checklist

Applied in addition to the [universal checklist](../../docs/review-checklist.md), sections A and B.

- [ ] Read all versions side by side; confirm no contradiction
- [ ] Paste the alert text into the actual notification system to verify length
- [ ] Read the radio script aloud
- [ ] Click every link and dial every number
- [ ] Confirm no individual could be identified from any version
- [ ] Confirm the Emergency Manager approved these facts for release

## Known failure modes

| Failure | How to catch it |
| --- | --- |
| Versions contradict on times or instructions | Side-by-side read before approval |
| Alert text exceeds the limit | Paste into the real system; do not trust the stated count |
| Adds reassurance or a cause not in the input | Check each sentence against the input bullets |
| Invents a hotline, shelter, or hours | Verify every contact point and location |
| Radio script reads like written text | Read it aloud |
| Buries the action at the end | Confirm the action is in the first two sentences |
| Drifts into emergency-management jargon | Read as a resident, not as staff |
